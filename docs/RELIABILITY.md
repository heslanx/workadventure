## Phase 7 gate

**Verdict: PARTIAL.** Every hot flow has a failure-mode table, a timeout inventory, a degradation ladder and SLO proposals. No failure has been injected and measured, so every target behaviour below is unverified.

Why the gate stays open:

1. No failure drill exists. No run has killed a back, restarted a pusher under load, or cut LiveKit, Redis or map-storage. The generator can make bots leave (`--disconnect-fraction`, `benchmark/README.md:85`) but cannot make them rejoin, so a reconnect storm cannot be produced today.
2. No valid 1000-bot run exists. The only one was ramp-dominated: a 40 s ramp inside a 45 s run, 823 of 1000 accepted, all 969 close events at code 1006 when the Colima forwarder died (MEASURED, `PERF/load-1000.json`: `config.rampSeconds` 40, `wallSeconds` 45.003, `closeCodes` `{"1006": 969}`). This machine must never run more than 300 bots; 1000 runs only on the Linux load host (DEC `decisions.md:56`; `docs/PERFORMANCE.md:203`).
3. The release path does not run the fork's server code. `deployment/konclui/compose.yaml:24,60,74` pins the official `workadventure-play`, `-back` and `-map-storage` images at `v1.34.5`. The stale-resume refusal, the move token bucket, the shed counter, the sub-message counters, `MAX_P2P_PEERS` and the LiveKit `createRoom` fix exist only in fork-built images.
4. The same compose sets no `PROMETHEUS_PORT` or `PROMETHEUS_AUTHORIZATION_TOKEN`, so both `/metrics` endpoints answer 501 (`back/src/Controller/PrometheusController.ts:15-18`, `play/src/pusher/controllers/PrometheusController.ts:23-26`). No counter in this document is scraped where users are.
5. The pusher, the measured bottleneck (CPU max 143.65% of one core at 823 bots, MEASURED, `PERF/load-1000-stats.log`), has no overload control of its own (see the backpressure map).

The gate passes when R-01 to R-05 below are closed and one back-kill drill and one pusher-restart drill have run at 300 bots on this machine and at 1000 on the Linux host, each with its SLO row measured.
