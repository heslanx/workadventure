## Debt Budget & Broken-Windows Policy

- Every change to `GameScene.ts` adds or extends a test at the nearest pinch point (`update()` for remote players, `pushPlayerPosition`/`handleCurrentPlayerHasMovedEvent` for the local player) before the edit lands.
- New logic does not go inline into `GameScene`. It is sprouted as a class or pure function with its own tests and called from one line.
- Structure-only and behavior-only changes ship as separate commits. A bug found while characterizing is pinned first, then fixed in its own commit where the pinned test flips.
- Budget: each module pass pays down at least one P1/P2 ledger row, or adds the pins that make one safe to fix.
- Broken windows: no new commented-out code, no new `throw` in the frame path, and no new definite-assignment (`!`) field without an initializer or a comment saying who sets it.

## Adopted Conventions

- Naming and error handling follow the project's own guides: `docs/agent/typescript-style.md` (match the module's convention, no `any` or `as`, no floating promises, `AbortController` for cancellable work) and `docs/agent/error-handling.md` (custom errors, narrowing `unknown`, report the `Error` object to Sentry, exhaustive switches). Phase 3 judges code against them (decided 2026-11-12).
- GameScene characterization tests build the real scene: `new GameScene(fakeRoom, key)` runs the real field initializers, repository and interpolator. Only methods that need a running Phaser game are replaced, on the instance (`doAddPlayer`, `getViewport`). Collaborators (`connection`, `activatablesManager`, `gameMapFrontWrapper`) are injected as fields for sensing.
- Module-level spies replace DOM-bound singletons (`biggestAvailableAreaStore.consumePendingRecompute`, `iframeListener.hasPlayerMoved`) and are restored in `afterEach`.
- Ledger IDs use the form `GS-nn`. A pinned bug carries its ID in the test name and comment, and its fix patch flips that test.
- Probe first: assert a value that is deliberately wrong, read the failure, then pin the observed value.
- `SocketManager` characterization tests build a real `SocketManager`, and real `PusherRoom`, `PositionDispatcher`, `Zone` and `Space` objects. The back is a fake `apiClientRepository.getClient` that returns one `FakeStream` per `connectToRoom()` and per `listenRoom()`. The space back is a fake `SpaceConnectionInterface` passed to the constructor. Tests assert on what the sockets and the streams receive, not on the manager's maps.
- Ledger IDs for this module use the form `SM-nn`.
