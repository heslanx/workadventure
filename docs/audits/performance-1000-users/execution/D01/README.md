# D01a: TypeScript 6 compatibility line (TS 5.9.3 -> 6.0.3)

Status: PARTIAL deliverable, verified on a remote copy only. Nothing applied to the checkout.
Scope: CI/dev typecheck and build tooling. This says nothing about runtime, room capacity or the 1,000-user target.

## Where it ran

- Host knc, container `wa-fable-ts` (image node:24-trixie, `--cpus 2`, 8 GiB, `--cpu-shares 512`, label owner=wa-fable-20261111), tree `~/wa-jobs/wa-fable-20261111/src-wa-fable-ts` mounted at `/work`.
- Remote originals were checked byte-for-byte against the checkout `HEAD` (ddbe245a8): 14/14 files equal, `package-lock.json` included. The 3 `contrib/tools/*` files had no remote original. Their patch hunks are computed against `git show HEAD:<path>`.
- Measurements use `tools/measure.py` (wait4 accounting, the same source GNU time reads; peak RSS = largest single descendant).

## Patch

- `d01a-ts6-compat.patch`: 16 files, 207 lines. Unified diff against `HEAD`. `git apply --check` exit 0 on a `HEAD` copy.
  - 12 manifests: `"typescript": "^5.9.3"` becomes `"^6.0.3"` (root, back, map-storage, play, benchmark, libs/{map-editor,math-utils,messages,shared-utils,store-utils}, contrib/tools/{e2e-report,generate-env-docs}).
  - Config fixes that TS 6 needed (all applied in the measured tree):
    - `libs/messages/tsconfig.json`: `"types": ["node"]`. TS 6 no longer pulls in `@types/node` by default: 6 errors before (TS2591 fs/url, TS7017, TS2339 import.meta.url).
    - `contrib/tools/e2e-report/tsconfig.json`: `"types": ["node"]` (28 errors before: TS2584 console, TS2591 process/node:child_process, TS7006).
    - `play/tsconfig.json`: `"rootDir": ".."` (1 error before: TS6059. `vite.config.ts` imports `../libs/messages`, and the TS 6 rootDir default is now the tsconfig dir).
    - `play/tsconfig-pusher.json`: drop the removed `preserveValueImports`, add `"rootDir": "."`. `--showConfig` before/after captured remotely (`/tmp/wa-meas/pusher-showconfig-{before,after}.json`).
- Lock after the D01a install (not in the patch): `/tmp/wa-fable-staging/D01/package-lock.after-d01a.json`, sha256 `347f3a263087d06f093ee3389e70b8de5678a79a600d462c49b5a6818e7525bf`. It was regenerated by the previous agent from the `HEAD` lock. A reviewer should regenerate it with `npm install` rather than trust a copied lock.

- Only the forced `--outDir` probe fails, exit 2 with TS5011 (rootDir must be explicit). Adding `"rootDir": "./src"` would harden this, but it is neither applied nor verified.

Timing, TS 6 vs 5.9.3. Same container, `npm run -s typecheck`, 4 runs each for 5.9.3:
- back: wall median 10.70 s (8.83-12.62), user CPU 14.17 s, peak RSS about 899 MiB.
- map-storage: wall median 6.04 s (5.67-6.18), user CPU 9.59 s, peak RSS about 637 MiB.

TS 6 numbers are in `../P6/README.md`. The user CPU difference is under 3 %, which is within noise. D01a is a compatibility step, not a speedup.

## Blockers / blocked_with_reason

- typescript-eslint 8.60.0 (and its parser and typescript-estree): peer `typescript >=4.8.4 <6.1.0`. TS 6.0.3 is inside the range and lint ran with exit 0. Any TS above 6.0.x is blocked until typescript-eslint widens its peer range.
- svelte-check 4.4.8: peer `>=5.0.0`, ran with exit 0 on the TS 6 API.
- libs/messages: the `--outDir` emit probe gives TS5011 (see above). It is not on the real build path.
- Lock: generated remotely. It must be regenerated upstream. `npm install` was not run in the checkout.
- Not covered: full vitest suites, Docker image builds, and the `play` vite production build under TS 6.
