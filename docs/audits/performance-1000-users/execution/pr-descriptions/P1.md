## CLI contract

Every option can be set by env var or by flag; flags win.

| Env var | Flag | Default | Meaning |
|---|---|---|---|
| `WA_PUSHER_URL` | `--pusher-url` | required | http(s) base of play/pusher (`/anonymLogin`) |
| `WA_WS_URL` | `--ws-url` | `WA_PUSHER_URL` | WebSocket base if it differs (no reverse proxy) |
| `WA_ROOM_URLS` | `--room-urls` | required | comma-separated; session `i` joins room `i mod n` |
| `WA_SESSIONS` | `--sessions` | required | integer ≥ 1 |
| `WA_RAMP_SECONDS` / `WA_DURATION_SECONDS` | `--ramp-seconds` / `--duration-seconds` | 10 / 60 | session `i` starts at `i × ramp / sessions`; the duration includes the ramp |
| `WA_MOVE_HZ` | `--move-hz` | 1 | moves per second per accepted session; 0 = idle |
| `WA_API_VERSION` | `--api-version` | `dev` | must match the pusher's `apiVersionHash` |
| `WA_DISCONNECT_FRACTION` / `WA_DISCONNECT_AT_SECONDS` | `--disconnect-fraction` / `--disconnect-at-seconds` | 0 / duration ÷ 2 | share of sessions (lowest indexes) that leave early, and when |
| `WA_MIN_ACCEPTED` | `--min-accepted` | 1 | below this, the run is invalid |
| `WA_OUTPUT` | `--output` | none | also write the summary to a file |

The full table is in `benchmark/README.md`.

Exit codes:

- `0`: valid run.
- `1`: configuration or fatal error.
- `2`: the run finished but is invalid (not reconciled, or fewer accepted sessions than `WA_MIN_ACCEPTED`).

SIGINT and SIGTERM stop the run and still print the summary.

The summary is JSON on stdout. It holds:

- sessions: requested, started, accepted, rejected, aborted before join, unexpected closes, unique user ids;
- sockets opened, peak and closed;
- join latency p50, p95 and max;
- per-room counts, sent and received counts by event type, rejection reasons, errors and close codes;
- generator CPU, RSS and event-loop lag;
- cleanup state and a `reconciled` flag.

A session is accepted only on `roomJoinedMessage`. An error message, socket error, close or join timeout before
that counts as a rejection.

The 100-session run:

- accepted 100 with 100 unique ids, 0 errors and 0 unexpected closes;
- the server gauges read 100 during the run;
- 4946 moves were sent, against about 5010 expected for this ramp;
- join latency: p50 18.6 ms, p95 308.7 ms, max 987.1 ms (token request included);
- generator: 6.3% of one core, 167 MiB RSS peak, event-loop lag p99 13.6 ms;

These numbers describe this capped, shared, dev-mode setup. They are not a capacity figure for WorkAdventure.

The live run found no harness defect, and no harness file changed after it.

## What this tool does not certify

- Client rendering, FPS or browser memory. Audio and video (WebRTC, LiveKit), Matrix chat, the map editor or
  scripting API traffic.
- That a real browser shows the bots correctly. Lane 3 used a headless observer.
- Capacity at 1,000 users. Nothing above 100 sessions has run, and 1,000 sessions from one process is untested.
  Watch `generator.cpuPercentOfOneCore` and `eventLoopLagMs.p99`, and split the population across processes or
  hosts that do not share CPU with the server.
- Reconnection and resume (`lastReceivedNonce`). A dropped socket is counted, not retried.
- The coordinates of observed moves and the ids in leave events. The harness counts event types only.
