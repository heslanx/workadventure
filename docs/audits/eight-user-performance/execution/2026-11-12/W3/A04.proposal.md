# A04 proposal: deepen the existing delivery, retention and recovery guarantees

Status: proposal only, static, 2026-11-12. No product edit. Inputs: `architecture.md` A04, W3 `README.md`, current sources.

## Ownership boundary

- `play/src/common/NoncedMessageStore.ts` and `play/src/pusher/services/PusherWebSocket.ts` belong to **upstream PR #6688**.
  This proposal does not change them; it lists what a review of #6688 should verify.
- The backend CPU shedding (H15/H16) is a separate policy in `back/src/Services/SocketManager.ts`; its measurement fix is
  the W3 proposed patch, not part of A04.

## Guarantees that already exist (keep them)

| Guarantee | Where |
|---|---|
| uWS backpressure: `send` result 0 = buffered in order, 2 = dropped; only a dropped message is re-sent on drain; feeding stops until drain | `PusherWebSocket.ts` L326-333 |
| Transport ping with its own backpressure flag; keepalive across proxies | `PusherWebSocket.ts` L76-77, L281-288 |
| Socket swap keeps logical state (room, back stream, subscriptions); refuses replacement with close 1008 when the store lacks the nonces to replay | `PusherWebSocket.ts` L162, L206-223, L256 |
| Time-bounded retention, default 30 s, no byte/count bound | `NoncedMessageStore.ts` L12-15, L60 |
| Client nonces outgoing messages, retains them for replay, reconnects with attempt tracking | `WorkAdventureWebSocket.ts` L40-43, L68-74 |
| Final stopped position survives backend overheat (only `moving === true` is dropped) | `back/src/Services/SocketManager.ts` L261 |

## Deletion test

- Delete the store: reconnection semantics disappear or move into every consumer (each would re-implement replay windows).
  The complexity does not vanish, so the store is earning its place.
- Delete the drain/flush handling in `PusherWebSocket`: callers would need to know uWS return codes and ordering rules.
  Same verdict.
- Add a facade that only forwards queue calls: no complexity removed, one more indirection. Rejected.

## Proposal

1. Define message classes before any limit: durable events (must replay or fail explicitly) versus superseded state
   (positions, where only the latest matters). Only the second may ever be coalesced.
2. Make exhaustion explicit at the existing owners: when retention would exceed a bound, end with a visible, tested close
   (as 1008 already does for missing nonces), never a silent drop of durable state.
3. Expose observable figures from the same owners: buffered bytes, retained count/bytes, drain duration, replay size. These
   are the H18 discriminators; without them the freeze-ends-in-a-burst question cannot be answered.
4. No universal CPU/network/frame controller. Transport ordering, backend CPU shedding and scene event application keep
   separate owners and separate tests.

## Test surface (reuse, do not invent seams)

`play/tests/front/Connection/WorkAdventureWebSocket.test.ts` (factory + `FakeWebSocket`), the pusher socket tests under
`play/tests/pusher/`, and `back/tests` for shedding. Cases: patch/response order across a drain, bounded exhaustion,
replay without duplication, final position under overheat.

## Gate

Do not start before H18 is measured with a slow consumer and PR #6688 has landed or been declined. New limits must not
silently discard durable state. Rollback must consider connected clients, nonces and replay compatibility.
