# A02 proposal: concentrate the proximity-session lifecycle

Status: proposal only, static plus the existing tests in `logs/`. No product edit. Input: `architecture.md` A02.

## Where the lifecycle knowledge lives today

| Concern | Owner today | Source |
|---|---|---|
| Abort a join whose bubble dissolved, so a queued leave does not wait the 9 s `getFirstUsers` backstop | `ProximitySpaceManager` (`pendingJoins` + `AbortController`) | `play/src/front/WebRtc/ProximitySpaceManager.ts` L14-49 |
| Leave during an in-flight join, stale leave, default-room serialization, aborted join not reported to Sentry | `ProximityChatRoomManager` | `play/src/front/Chat/Connection/Proximity/ProximityChatRoomManager.ts` L109 and its test |
| Concurrent joins of one space coalesce (name reserved before the first await) | `SpaceRegistry` | `play/src/front/Space/SpaceRegistry/SpaceRegistry.ts` L341-351 |
| Provider switch with delay and cancellation | backend `CommunicationManager` | `back/src/Model/CommunicationManager.ts` |

The operation identity (which join a leave cancels) is known in two front modules with two different keys: space name
in `ProximitySpaceManager`, visual room key in `ProximityChatRoomManager`.

## Deletion test

- Delete the forwarding between `ProximitySpaceManager` and `ProximityChatRoomManager`: the simple pass-through goes
  away, but abort and ordering rules do not; they would reappear in every bubble/zone entry point. So the complexity is
  real and should be concentrated, not removed.
- Delete `SpaceRegistry` coalescing: duplicate spaces and leaked remote users return (its own comment, L341). Keep it
  where it is: it owns transport ownership of the space.

## Proposal

1. One existing module (first candidate: `ProximitySpaceManager`) owns the operation identity and its cancellation from
   start to completion; chat keeps history and visual state; the registry keeps the space transport. Decide whether it fits
   the existing module before creating one.
2. Reuse the concrete seam `RoomConnectionForSpacesInterface` with `MockRoomConnectionForSpaces`. Do not add a generic
   lifecycle interface that only renames the modules.
3. Test through that interface: rapid enter/leave/re-enter, abort before the first peer, stale leave, destroy during join,
   history preserved. The existing cases in the four front test files (37 passing) are the regression floor.

## Gate (not met in this round)

Start only after either (a) a rule shown to be needed by more than one consumer with diverging behavior, or (b) a
reproduced ordering/cancellation failure. The 116 existing tests reproduced none (`README.md`). The external `destroy` that
only removes a subscription is a signal to review ownership, not proof of a leak. Rollback must keep today's guards.
