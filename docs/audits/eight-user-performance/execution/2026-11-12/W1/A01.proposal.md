# A01 proposal - conversation bubble update and drawing (D02)

Decision: **deferred, gated on H01 evidence.** A01 stays "worth exploring" as an architecture debt; no product change is proposed in this window.

## Why not now

1. The incident cost of the bubble path is unmeasured. The mechanism exists (`play/src/front/Phaser/Entity/ConversationBubble.ts:193-265`: build Graphics, remove the previous texture, generate a new one, destroy the Graphics), and the scene already filters which bubbles need to advance (`play/src/front/Phaser/Game/GameScene.ts`, bubble selection cited by `architecture.md` A01). There is no evidence of an unconditional redraw.
2. A01 is a depth/locality change (move membership, influence radius and redraw decision into the bubble module). That improves where the rules live; by itself it promises no frame-time gain. Shipping it before H01 is measured would mix a refactor with a performance claim.
3. No browser or GPU measurement was possible in this window (`../W0/README.md`).

## Gate (what turns this into a change)

| Condition | Measured how | Then |
|---|---|---|
| `drawSpline` + `generateTexture` self time is a visible share of frame time with 8 users walking in one bubble, beyond the spread of two repetitions | browser Performance trace, runbook in `../W0/README.md` section 3 | smallest fix first: redraw only on geometry change, or reuse the Graphics/texture; measure before and after |
| the fix needs knowledge the scene holds today (membership, influence, avatar conversion) | code reading during the fix | deepen the bubble module (A01) in the same PR, keeping contour, smoothing, simultaneous groups and texture disposal |
| bubble cost is negligible in the representative trace | same trace | close H01 without optimization; keep A01 only as a readability debt |

## Preserve

Contour and smoothing, several simultaneous groups, texture disposal on destroy (`ConversationBubble.ts:287`), and the existing affected-bubble filtering. Do not add a pass-through module that only forwards calls.

Owner: rendering. Next discriminator: H01 browser trace (8 users, close vs apart, still vs walking).
